# MVP roadmap

## Phase 1: Problem validation and discovery

Goals:

- talk with early-adopter labs
- understand real MRD workflows and pain points
- decide which assay types to support first

Deliverables:

- lab discovery notes
- pipeline requirements for the chosen MRD workflow
- UI mockups for key reporting screens

## Phase 2: Core pipeline prototype

Goals:

- build a small end-to-end workflow for a narrow assay type
- validate output quality against a known benchmark or reference dataset

Deliverables:

- AWS workflow skeleton
- sample upload flow
- basic result generation
- QC tracking

## Phase 3: Clinical reporting MVP

Goals:

- create a basic React dashboard for sample and result review
- add trend charts and MRD summaries
- produce a clinically readable report

Deliverables:

- result dashboard
- clone tracking visualization
- final summary report view

## Phase 4: Pilot lab validation

Goals:

- deploy to one or two early labs
- compare outputs with orthogonal methods
- collect feedback and improve the product

Deliverables:

- pilot-ready assessment reports
- identified changes for version 2
- LOD and reporting thresholds defined more clearly

## Phase 5: Hardening for launch

Goals:

- improve reliability, access controls, and validation coverage
- refine clinical workflows and documentation

Deliverables:

- more robust QA pipeline
- compliance-ready workflows
- stronger patient/result traceability

## Recommended first hire priority

The first technical hire should focus on:

- end-to-end pipeline execution
- a working MVP interface
- validation of output quality
- early customer feedback loops

This is not a role only for backend engineering or only for frontend work. It needs a strong generalist with hands-on execution ability.
