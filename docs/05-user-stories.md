# MVP user stories

## Lab user stories

- As a lab technician, I want to upload a sample and its metadata so that analysis can begin.
- As a lab manager, I want to see sample status and QC metrics so that I can understand risk and quality.
- As a scientific lead, I want to compare results across assay types so that I can validate method consistency.

## Clinical reporting stories

- As a physician, I want to see a clear MRD trend over time so that I can assess treatment response.
- As a clinician, I want to view concordance between methods so that I can trust the report.
- As a reviewer, I want to inspect clone tracking so that I can understand the clinical interpretation.

## Platform stories

- As a platform engineer, I want Step Functions-based orchestration so that workflows are reliable and auditable.
- As a data steward, I want secure storage and traceability so that patient data remains compliant.
- As a founder, I want a working MVP for a pilot lab so that I can validate product-market fit.

## Example product priorities

1. Basic sample upload and workflow run
2. BCR/TCR analysis with result summary
3. Clone frequency visualization
4. QC thresholds and error review
5. Physician-facing reporting summary

## Definition of MVP done

The MVP is done when a lab can upload data, run a defined MRD workflow, review QC, and see a physician-facing result summary without manual intervention.
